# Ingestion — `scratch-pad` → Backpack (and Hoard)

`scratch-pad` is the strongest work-state producer in the ecosystem. It is
where active QA reality gets externalized into files. This doc specifies how
those files become Backpack entries (primary) and Hoard records (artifacts and
dailies).

## What `scratch-pad` actually contains

Verified against [snackdriven/scratch-pad](https://github.com/snackdriven/scratch-pad):

- `backpack.json` — the legacy single-file Backpack. Source of truth today.
- `.backpack_memory` — assistant-side carry hint file.
- `dailies/YYYY-MM-DD/` — per-day folders with HTML dashboards, transcripts,
  ticket artifacts, screenshots.
- `dashboard-manifest.json` — a generated manifest listing today's tickets and
  artifacts (e.g. `TTOAD-328-retest-plan.md`, screenshots, jira-comments).
- `.claude/hooks/` — pre-compact, statusline, memory-reminder, prompt-submit
  hooks. These are the closest thing scratch-pad has to a runtime.
- `.claude/skills/` — packaged skill bundles (e.g. `qa-daily-summary-auto`).
- `.claude/scripts/` — sync scripts (Argo, Sheets).
- `templates/`, `assets/`, `autofill/` — supporting material.

Three families of material come out of this:

| Family | Examples | Lands in |
|---|---|---|
| **Working state** | qa-queue snapshot, meeting summary, ticket status, fast-follow status | Backpack (primary) |
| **Artifacts** | screenshots, HTML reports, retest plans, jira-comments markdown | Hoard (with attachment pointer) |
| **Dailies** | a whole `dailies/YYYY-MM-DD/` folder | Hoard timeline-event + per-artifact items |

## The four scratch-pad adapters

### A. `dashboard-manifest.json` adapter

**Source:** `dashboard-manifest.json` regenerated by scratch-pad's daily
process. Contains `today.date` and a per-ticket file listing.

**Maps to:**
- One Backpack item per active ticket: id `qa-ticket-<TICKET>-<YYYY-MM-DD>`,
  memory-class `expiring-tactical`, freshness-class `current`, scope `work`,
  ttl `604800` (1 week, matching observed pattern).
- One Hoard `artifact` item per file in the manifest, with
  `attachment.path` pointing at the file relative to scratch-pad root and
  `attachment.sha256` hashed at ingestion time.
- One Hoard `timeline-event` per day (id `daily-<YYYY-MM-DD>`) summarizing
  the manifest, linking all artifacts via `tags` and `projects`.

**Idempotency key:** `(ticket_id, date, artifact_sha256)`. Re-running over the
same manifest produces no new writes.

**Replacement:** When a new manifest lists the same ticket on a later date,
the new ticket-snapshot is written to Backpack with
`replaces: qa-ticket-<TICKET>-<previous-date>`. The predecessor moves to
`backpack/_replaced/`.

### B. `dailies/YYYY-MM-DD/` adapter

**Source:** A whole daily folder. Triggered when a folder is sealed (last
modification > 24h, or a `_sealed` marker file).

**Maps to:**
- All transcripts (`transcripts/*.txt` + `*.md`) → Hoard `transcript` and
  `transcript-summary` records (see [04-transcripts.md](./04-transcripts.md)
  for the transcript subspec; this adapter delegates).
- The `daily-*.html` page → Hoard `artifact` (attachment).
- An EOD summary if present → Hoard `session-summary` (id from
  `eod-YYYY-MM-DD`, scope `work`).
- An optional Backpack `timeline` entry summarizing the day if the daily is
  long enough to warrant a rollup (default: ≥3 transcripts or ≥1 release
  event). Otherwise the day stays in Hoard only and the rollup happens at
  week boundary.

**Idempotency key:** `daily-<YYYY-MM-DD>`. Once a daily is ingested, the
adapter refuses to re-ingest unless the user passes a force flag.

**Note on `.html` artifacts:** scratch-pad stores HTML dashboards as the
visual artifact format. The adapter does NOT parse them for content; it
treats them as opaque attachments. Content lives in the markdown summaries
that accompany them.

### C. `backpack.json` migration adapter

**Source:** the legacy `backpack.json`. Run once during migration to the
file-system-as-database layout, plus on demand if a fallback edit lands in
the legacy file.

**Maps to:**
- Each non-`_config:*` key → a `backpack/<freshness>/<id>.md` file.
  Freshness folder chosen from the `backpack-freshness-guide` value, falling
  back to `current` for items dated within 1 day, `recent` within 7,
  `contextual` within 28, `historical` otherwise, `evergreen` for keys
  matching the documented evergreen list (`user-profile`, `team-roster`,
  `writing-preferences`, `jira-boards`, `nhha-architecture`,
  `deploy-knowledge`, `qa-workflows`, `db-and-billing-ref`, `reorg-context`,
  `qa-tooling-refactor`, `e2e-testing`, `chorus-company-profile`).
- `_config:pinned_keys` → set `freshness_class: pinned` on every listed item
  AND record the canonical pinned list in `policy/freshness.json#pinned_keys`.
- `_config:ttl` → set `created_at` and `ttl_seconds` on the corresponding
  item's frontmatter. `_config:ttl[*].replaces` becomes the item's
  frontmatter `replaces`; the named predecessor is moved to `_replaced/`.
- Raw-string entries → frontmatter `value` with the original string preserved
  verbatim (raw-string remains valid per the schema).

**Verification:** The adapter MUST emit a `migration-summary` event listing
counts by freshness class, count of items moved to `_replaced/`, and any
items that could not be classified (these go to `backpack/_unclassified/` for
manual review rather than being silently placed).

**Note:** Per `06-design-principles.md`, the legacy file remains hand-editable
during the migration window. The adapter must support a "merge from legacy"
mode that detects stale on-disk frontmatter vs. fresh legacy keys and prefers
the legacy version, then re-runs migration.

### D. `.claude/hooks/` runtime adapter

**Source:** scratch-pad's hooks emit small JSON payloads to stdout/stderr or
to a `.claude/events/` drop folder.

**Maps to:**
- `pre-compact-auto-save.cjs` payloads → Hoard `session-summary` (one per
  Claude session compaction). Carries the conversation window's distilled
  context.
- `user-prompt-submit.js` payloads (when the user explicitly tags a prompt
  for capture) → Hoard `note` or `scrap`.
- `context-monitor-statusline.cjs` payloads → ephemeral; do NOT ingest.
  Statusline is a renderer, not a source.
- `memory-reminder.sh` payloads → not ingested. The hook's job is to emit
  reminders at runtime, not to write substrate.

**Idempotency key:** session id + timestamp.

## Frontmatter generated by these adapters

Every Backpack item written by scratch-pad adapters has, at minimum:

```yaml
id: <kebab-case-id>
freshness_class: current | recent | contextual | historical | evergreen | pinned
memory_class: expiring-tactical | replaceable-truth | pinned-doctrine | evergreen-reference | timeline
scope: work
dated: YYYY-MM-DD
created_at: ISO-8601
ttl_seconds: <one of 604800, 1209600, 2592000, 7776000>
source:
  kind: scratch-pad
  ref: <path relative to scratch-pad root>
tags: [...]
```

Additional fields (`replaces`, `hoard_refs`, `renderer_hints`,
`doctrine_ref`) are filled in by the adapter when applicable.

## Renderer-hint defaults

Scratch-pad adapters set renderer hints conservatively:

- Active QA tickets (e.g. `qa-ticket-TTOAD-367-2026-04-29`) →
  `surfaces: [dashboard, daily-brief, session-primer]`, `priority: 80`.
- Meeting summaries → `surfaces: [dashboard, daily-brief]`, `priority: 70`.
- Daily timelines → `surfaces: [session-primer]`, `priority: 30`.
- Pinned doctrine items → `surfaces: [session-primer, dashboard]`,
  `priority: 95`, `decay: never`.

Adapters SHOULD NOT set `surfaces: [narrator]`. Narrator selects what to
voice from its own routing rules; ingestion does not push items at it.

## Ordering and conflicts

If `dashboard-manifest.json` and a manual edit to a `backpack/current/*.md`
both touch the same item:

1. The hand-edit wins. Manifest ingestion compares its derived frontmatter to
   the on-disk file's frontmatter; if any field differs and the on-disk file
   has a `created_at` newer than the manifest's `generatedAt`, the manifest
   write is skipped and an event is emitted with status `superseded-by-hand`.
2. If both are stale relative to the legacy `backpack.json`, the legacy file
   wins (per `github-source-of-truth` doctrine extended to local files: the
   most recently hand-edited source wins).

## Failure modes scratch-pad ingestion guards against

- **Manifest regeneration races.** The adapter reads `generatedAt` and stamps
  it on every derived item; later manifest runs detect their own staleness.
- **Duplicate ticket entries across days.** Idempotency key includes date, so
  the same ticket on two days produces two distinct entries; the newer one
  has `replaces` set to the older.
- **Orphan artifacts.** A screenshot or jira-comment that is no longer in the
  manifest is NOT deleted from Hoard. Hoard is write-once. Orphans become
  searchable history.
- **Stale `.backpack_memory`.** This file is treated as a hint, not as truth.
  The adapter never writes Backpack entries from it; it may emit a
  `hint-observed` event so renderers can show "the assistant thinks X is
  near."
